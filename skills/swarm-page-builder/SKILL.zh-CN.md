# Swarm页面施工

使用随包附带的可编辑源码，在用户自己的工程文件中实现多光标协作施工页面。效果参考[swarm-cursors](https://github.com/DhvanilPatel/swarm-cursors)，通过React组件、调度引擎、场景构建器、点击映射及本地配置弹窗落地，访问者直接打开页面即可体验。运行时不需要本技能、不加载原站压缩脚本、不接入真实AI服务。

# 1、选择接入方式

先查看目标项目的技术栈、路由、包管理器和现有文件，沿用目标仓库约定。

- **新建项目**：读取[接入说明](references/integration.zh-CN.md)的独立项目部分，用`standalone`模式复制完整Vite模板。
- **已有React项目**：读取[接入说明](references/integration.zh-CN.md)的模块部分，用`module`模式复制到新的功能目录，接入独立全屏路由。脚本不会修改宿主的入口、依赖或路由。
- **Vue、普通HTML等项目**：现成组件需要React。可把独立模板作为完整页面或iframe接入；需要原生框架实现时保留场景/任务协议，另写展示层和生命周期适配，不声称复制JSX即可运行。
- **只要光标装饰或任意局部容器效果**：现成模板不是这种组件。按用户范围提取或改造引擎，先说明需要调整坐标、滚动与渲染，不把整站硬塞入已有界面。

模板以浏览器文档为滚动容器，适用于一个页面中一个实例。不能放进有独立滚动、偏移或transform的局部面板。SSR应用从客户端组件边界接入，引擎只在浏览器effect中创建。

# 2、复制源码

将以下`<skill-dir>`替换为当前SKILL.md所在目录，不要猜测全局安装位置；目标路径必须是尚不存在的新目录。

```bash
python3 <skill-dir>/scripts/scaffold.py --mode standalone --target /path/to/new-project
python3 <skill-dir>/scripts/scaffold.py --mode module --target /path/to/existing-project/src/features/swarm
```

可加`--dry-run`查看复制计划。脚本只复制本地模板，不下载、安装、构建、提交或部署。目标已存在时停止，选择新的目录或人工合并已确认的差异，避免覆盖用户代码。

不要把`node_modules`、原站构建产物、机器配置或本项目绝对路径带入新项目。模板React/Vite版本只是独立示例的版本；已有项目沿用自己的依赖版本和包管理器。

# 3、适配页面

按需要读取[场景与交互协议](references/customization.zh-CN.md)。优先修改场景分区、主题和点击动作；动画调度保持独立。使用自定义场景时同时传入与之匹配的`interactions`，不保留指向已删除实体的默认热点。

`SwarmExperience`提供场景工厂、交互定义、动作回调和自动启动入口。文案、颜色、任务以及图形均保留可编辑源码。对需要真实业务行为的按钮，通过宿主`onAction`接管；本地方案预览不能包装成真实购买、申请或AI任务已执行。

保留以下关键约束：

- 文本与Canvas测量共用字体、字号和行高；字体变化后同步检查测量与换行。
- 热点等背景、文本、复制和替换任务完成后启用。复制元素使用`~1`开始编号，复制任务使用从`0`开始的索引。
- 可变实体按`v`版本刷新，修改实体后调用`markChanged()`；不要直接依赖React对象引用变化。
- 光标数量由`INITIAL/BASE/FOLLOW/MAXIMUM`共同控制。用户要求固定数量时需同时调整生成、退出和跟随逻辑。
- 本模块CSS限定在`.swarm-experience`下。宿主页面reset由宿主负责，不能把独立演示的`demo.css`全局复制进已有项目。

# 4、交付

根据目标仓库允许的验证方式检查入口、样式、点击任务ID、卸载清理与移动端显示。尊重用户对构建和测试的限制；仅人工审查时如实说明，不宣称已经运行验证。浏览器验收关注滚动施工、链接定位、弹窗关闭与焦点恢复、复制下载和切换路由后的监听清理。

交付目标文件、启动或路由入口、可修改位置和未验证项。保留[来源说明](references/provenance.zh-CN.md)，不将本模板称为上游作者原始开发工程，不替上游声明授权条款。
